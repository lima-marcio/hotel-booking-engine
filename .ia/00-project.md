# Project Guidelines

## Philosophy
- Build production-quality MVPs.
- Finish one complete feature before starting another.
- Reuse existing services, DTOs, validators, components and utilities.
- Avoid duplicate code.
- Prefer simplicity (KISS), YAGNI and readable code.
- Organize work by business features.
- Code, identifiers and technical documentation in English.
- Ask for confirmation before creating backend/ and frontend/ folders.
- Every project must be a Git repository.

# AI Autonomy

The AI is expected to work autonomously.

Do not ask for confirmation for routine development tasks.

Continue implementing until the current feature is fully completed.

Only interrupt when a decision may significantly change the project.
